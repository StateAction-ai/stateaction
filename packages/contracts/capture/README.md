# StateAction capture wire contract (SA-50)

`stateaction.capture.v1.1` is the single source contract for the H.264-in-MCAP capture profile `h264_mcap_v1`. Android (Kotlin), iOS (Swift), Flutter (Dart), TypeScript and Python readers/writers test against the same schemas and golden files. The profile is **unqualified**: nothing here claims physical-device, hardware-clock or training qualification, and no field claims model-relative 3D data is metric ground truth.

## Encoding rules

- MCAP header profile is **empty** (`""`): the file mixes Protobuf, CDR and JSON, so it must never claim the `ros2` profile.
- `/camera/rgb/video`: `foxglove.CompressedVideo`, schema encoding `protobuf`, message encoding `protobuf`, embedded descriptor hash must equal the pin. One complete Annex B **image** access unit per message (first image IDR, every IDR carries SPS+PPS, no B slices, codec configuration alone is not an image).
- Distinct identities that round-trip exactly: capture time (Protobuf `timestamp`, also the MCAP log time unless explicitly delayed), `frame_id` = optical frame name (a coordinate frame, never an image ID), `source_frame_id` (FrameEvent), video sequence (MCAP channel sequence = `output_sequence`), encoder PTS (`encoder_pts_us`, time base `1/1000000`), terminal outcome (`written` or `dropped` + reason).
- Original native clocks are preserved (`native_timestamp_ns`, `native_clock_id`, `native_timestamps`); the mapped capture time is derived evidence under `clock_mapping_revision`. `Clocks.stream_clocks` declares each stream's clock; mixing is a defect.
- IMU samples are independent raw `MotionEvent`s, not frame timestamps. CDR channels (e.g. `geometry_msgs/msg/PoseStamped`) use `ros2msg` schema + `cdr` message encoding.
- `Close` carries final frame/drop/video/sensor counts and a terminal outcome; counts must equal the observed lifecycle.
- Historical `sensor_msgs/CompressedImage` JPEG captures are classified `legacy_jpeg` and never accepted as `h264_mcap_v1`.

## Strict schemas (every reader)

- **Closed objects**: every object is `additionalProperties: false`, except the one explicitly bounded map `Clocks.stream_clocks` (1..32 entries, `label` keys, `clockDomain` values). `native_timestamps`, `limits`, `encoder`, `recorder_transport`, `frames`, `motion_events` (`accel` and `gyro`, both required) and every array item are closed. Producer fields outside the schema need a contract revision.
- **Identifiers**: `recording_id` is a domain entity ID, a canonical lowercase UUID (`common.v1#/$defs/uuid`). Textual labels are intentionally not UUIDs: optical frame names (`frame_id` in Protobuf/CDR), `calibration_id`, sensor/stream IDs, kinds, models and reason codes use `label` = `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`; `failure_reason` is `text` (1..256 printable ASCII) or `null`. Original sensor clocks and IDs are carried verbatim.
- **Bounds**: nanoseconds, PTS, source frame/event IDs and every Close count are exact `int64Decimal` strings (0..9223372036854775807, canonical decimal); `output_sequence` is a uint32 integer (the MCAP sequence); `pending_frames` 1..64; encoder raster 1..16384; IMU values are numbers in ±1e6 and exactly 3 per sample; `accuracy` -1..3 or `null`; `sensors` 1..64, `calibrations` ≤64, `drops` ≤32 items; clock domains/revisions use the published `clockDomain`/`revision` patterns. Unknown/unavailable states stay explicit (`unknown`, `unavailable`, `null` counts), never omitted.
- **Published common definitions**: `uuid`, `int64Decimal`, `clockDomain` and `revision` are copied verbatim from `../api/common.v1.schema.json` (SA-12) into each schema's `$defs` at build time, resolved offline, so every embedded MCAP schema stays self-contained; `build_schemas.py --check` and `verify.py` fail on drift. `label`, `text`, `uint32` and the capture `timeBase` (wire names `numerator`/`denominator`, fixed at 1/1000000) are capture-owned; the capture namespace stays in this directory and the API package does not depend on it.
- **Gate**: each reader validates every JSON message against the reviewed contract schema for its topic (never the copy embedded in the file, which is only hash-compared, `E_SCHEMA_MISMATCH`). Any violation stops evaluation with `E_SCHEMA_MALFORMED` and the exact sorted violations as `facts.schema_violations` (`<topic>[<message index>]<instance pointer>:<keyword>`), which every runner must reproduce byte for byte. Schema-level defects that previously had dedicated codes (missing PTS, non-integer PTS, wrong time base, numeric timestamps) are now reported this way. After the gate, `/stateaction/{capture_profile,clocks,inventory,close}` must each appear exactly once (`E_CHANNEL_CARDINALITY`) and every JSON message must carry the same `recording_id` (`E_RECORDING_ID`).
- **Portable interpreter** (`strict_schema.py` and its TS/Dart/Kotlin/Swift ports): supports exactly `$schema $id $defs $ref title description type const enum required properties additionalProperties propertyNames minProperties maxProperties items minItems maxItems pattern minLength maxLength minimum maximum anyOf allOf if then`. Loading a schema with any other keyword, a non-local `$ref`, an unanchored/non-ASCII pattern or an unknown type fails closed (`fixtures/schema_cases.json#unsupported_schemas`). Semantics shared by all ports: `integer` = finite number with zero fraction (booleans are never numbers); patterns must match the whole string, so a trailing newline never satisfies `$`; lengths count code points; `const`/`enum` use deep JSON equality (1 == 1.0, `true` != 1). JSON text is parsed strictly (RFC 8259 plus the RFC 7493 I-JSON surrogate rule): a leading UTF-8 BOM (`EF BB BF`, never stripped), invalid UTF-8, nesting deeper than **32** open arrays/objects (checked before recursion, so the bound and not the runtime stack decides; the same `maxDepth` as `../api/catalog.v1.json`), duplicate keys, `\u` escapes that leave an unpaired surrogate, `NaN`/`Infinity` and numbers that overflow a double are `E_MALFORMED_MESSAGE`. Object keys are compared as exact code point sequences, never Unicode-normalized: `"\u00e9"` and `"e\u0301"` are distinct keys, while an escaped and a literal spelling of the same code points are a duplicate. Pointer tokens percent-encode the UTF-8 bytes of the actual scalars (`fixtures/schema_cases.json` covers BOM, depth 32/33 including deep unknown values and 20,000 levels, lone/reversed surrogates, U+FFFD, astral pairs and composed/decomposed keys) (Kotlin and Swift use their own strict parser because org.json and Foundation are lenient or conflate booleans with numbers).
- **Oracle**: `verify.py` validates every parseable JSON message in the corpus, mutations of each, the protocol fixture and the direct cases with both the portable interpreter and `jsonschema` `Draft202012Validator` (with whole-string pattern matching) and requires identical violation sets (8,416 instances locally).

## Container layout and integrity (every reader)

The portable readers accept exactly one MCAP layout: magic; `Header` as the first record; only `Schema`, `Channel` and `Message` records in the data section; exactly one `DataEnd` whose `data_section_crc` is **nonzero** and equals CRC-32 (IEEE, as `zlib.crc32`) of every byte before the `DataEnd` record, leading magic included (the official readers' definition); a `Footer` with `summary_start = summary_offset_start = summary_crc = 0`; the closing magic and end of file. MCAP major version `0` (`\x89MCAP0\r\n`) is the only supported version.

- `E_DATA_CRC`: CRC zero (unavailable) or mismatched. The official reader treats 0 as "not available"; this contract does not.
- `E_UNSUPPORTED_LAYOUT`: chunks, message indexes, attachments, metadata, statistics or any summary/index record, a footer that points at a summary section, a missing `DataEnd`, records after `DataEnd`, or a `Header` that is not first.
- `E_TRUNCATED`: end of file before the footer/closing magic, a record that overruns the file, or a record string that is not valid UTF-8.
- `E_DEFINITION_ORDER`: checked while streaming, in file order. A `Channel` whose nonzero `schema_id` names no earlier `Schema` record, or a `Message` whose `channel_id` names no earlier `Channel` record (the official reader fails on both with `no schema/channel record found`).
- `E_DEFINITION_CONFLICT`: a `Schema` or `Channel` id redefined with a record body that is not byte-identical to the first definition, or a `Schema` record with the reserved id 0. Byte-identical repeats are allowed. The official reader silently follows the latest definition, so a conflicting file means different topics to different tools (`bogus_channel_redefined_after_messages` reads as 17 FrameEvents on `/bogus/topic` there).

All strings read from records and messages (topics, schema names, encodings, `frame_id`, `format`) are decoded as strict UTF-8 that keeps a leading U+FEFF (Dart's decoder strips it otherwise, Kotlin's and Swift's lenient decoders would substitute U+FFFD).

Production recorders may write chunked, indexed and compressed MCAP (`CaptureProtocol.profile` advertises chunk limits). Those files are outside the portable readers' layout and are **rejected, never reported complete**, by them; `verify.py --mcap <file>` reads them with the official `mcap` reader with `validate_crcs=True` (chunk and data CRCs) and applies the same strict schemas and descriptor/schema identity. A full chunk/index/summary checker in every language is not part of this contract.

## Frame lifecycle, counts and finalization rules (every reader)

- `acquired` once per `source_frame_id`; at most one `submitted`; exactly one terminal `written` or `dropped`, or none when the recording ended first (`unresolved`). Every later event must repeat the acquired identity: recording/stream, native timestamp and clock, mapped capture time and mapping revision, calibration id, `encoder_pts_us`, `encoder_time_base`, native timestamps (`E_FRAME_IDENTITY`). `encoder_pts_us` is a canonical int64 decimal and the time base exactly `1/1000000` (both schema-enforced, `E_SCHEMA_MALFORMED`), calibrations must be declared in the Inventory (`E_CALIBRATION_UNKNOWN`).
- Written `output_sequence` values are unique and equal the MCAP video message sequences one to one (`E_SEQUENCE`); video timestamp and IDR flag equal the written event (`E_VIDEO_TIMESTAMP_MISMATCH`).
- `Close` must equal the observed frame states, video messages, motion events per topic, sensor events and `drops` by reason (`E_COUNT_MISMATCH`). `completed` requires `unresolved == 0` and `failed` requires a `failure_reason` (`E_OUTCOME_MISMATCH`); `aborted`/`failed` files with unresolved frames are accepted when their counts are exact. A file without a footer/Close is `E_TRUNCATED`.
- Undecodable Protobuf/JSON/CDR messages or records are the defined reject `E_MALFORMED_MESSAGE`; JSON evidence that violates its strict schema is `E_SCHEMA_MALFORMED` with exact violations (see _Strict schemas_). Runners never crash on these inputs. `DataEnd` CRCs are required and verified (see _Container layout_).

## Encoder buffer sequences (partial / config contract)

`fixtures/encoder_buffers.json` is a contract-level fixture, independent of any producer: MediaCodec-style output buffers (`CODEC_CONFIG=2`, `PARTIAL_FRAME=8`, `END_OF_STREAM=4`, `KEY_FRAME=1`) built from NAL ranges of the public `golden/source/baseline-5.h264`, and the whole access units a writer must assemble from them, or the reject code. Codec configuration is stored and prepended to IDR access units without SPS/PPS; it never becomes an image. Chunks of one frame share a PTS and complete only on a buffer without `PARTIAL_FRAME`. Rejects: `E_INCOMPLETE_AU`, `E_PARTIAL_PTS_MISMATCH`, `E_MISSING_PARAMETER_SETS`, `E_MULTIPLE_ACCESS_UNITS`, `E_PTS_INVALID`. The MediaCodec producer that feeds real buffers is SA-51; this repo only fixes the expected assembly behaviour and tests it in all five language readers.

## Running

```sh
uv run --no-project --with jsonschema==4.25.1 --with mcap==1.6.0 --with protobuf==6.33.0 python packages/contracts/capture/verify.py
python3 packages/contracts/capture/conformance/run_all.py --require python,typescript,dart,kotlin,swift
pnpm exec nx run-many -t syntax,format,test -p capture-conformance,capture-conformance-mobile   # the CI path
```

`verify.py` validates schemas, pins, native asset identity, reproduces every expected result, validates all JSON evidence in accepted files against the embedded schemas, replays the encoder-buffer fixture, and independently decodes with the official `mcap` reader, the Protobuf runtime on the embedded descriptor and ffmpeg (decoded-frame count when ffmpeg and ffprobe exist; a missing ffprobe skips only that count). `run_all.py` fails closed: a runner listed in `--require` that cannot run is a failure, never a pass. Toolchain variables: `NODE_BIN`, `DART_BIN`, `GRADLE_BIN` (else the repository's Gradle wrapper) + JDK 21 `JAVA_HOME`, `SWIFT_BIN`.

Regenerate schemas and goldens: `python3 packages/contracts/capture/conformance/python/build_schemas.py && uv run --no-project --with protobuf==6.33.0 python packages/contracts/capture/conformance/python/gen_golden.py` (then `prettier --write` is not needed: the generated `fixtures/encoder_buffers.json` is in `.prettierignore`).

### Nx / CI wiring

- `capture-conformance` (`packages/contracts/capture/project.json`): `syntax` (incl. `build_schemas.py --check`), `format`, `test` (= `verify.py` + the TypeScript runner via `run_all.py --require python,typescript`). Runs in the server `checks` job through `nx affected`; inputs are the capture directory, `api/common.v1.schema.json` (implicit dependency on `contracts`), the native asset copies and the Android `data/h264` sources.
- `capture-conformance-mobile` (`packages/contracts/capture-mobile/project.json`): `format` (`dart format`) and `test` (Dart runner + Kotlin Gradle test via `--require dart,kotlin`). It is excluded from the server job and selected by the `mobile_projects` selector (alongside `contracts-dart` from SA-12), so it runs in the Android/Dart job where the pinned Flutter/Dart and JDK 21 exist (Kotlin uses `apps/mobile/android/gradlew`).
- **Swift is not run in hosted CI**: no Swift toolchain is provisioned on the hosted runner. The Swift 6.1.2 Linux runner passes locally (`SWIFT_BIN=... run_all.py --only swift --require swift`); this is a recorded hosted gap, not a pass.

## Provenance of the Protobuf descriptor

`schema-provenance.json` pins the upstream `foxglove-schemas-protobuf==0.4.0` wheel and sdist by SHA-256 and the exact rebuild command; `conformance/python/build_descriptor.py` rebuilds `foxglove-compressed-video.desc` from that wheel and verifies it is byte-identical to the committed descriptor. There are **no generated bindings** in this change: the descriptor is the Protobuf contract and each language reader contains a small hand-written decoder for the four-field `CompressedVideo` message (the Kotlin writer, `VideoWire`, is hand-written too). Generated code from the descriptor is not part of this ticket.

## Per-language scope and limits

- **Python**: reference checker and reference strict-schema interpreter; `verify.py` cross-checks the interpreter against `jsonschema` and decodes/validates CRCs with official libraries.
- **TypeScript (Node ESM), Dart, Swift, Kotlin `ContractReader`**: dependency-free full ports of the checker (MCAP, Protobuf, Annex B, CDR, ledger/lifecycle, close, channel and encoder-buffer rules). Each runs its port of the strict-schema interpreter on every JSON message, the DataEnd CRC/layout rules, and the direct schema cases; there are no third-party validators in these runners.
- **Kotlin native replay** (`NativeProtocolReplayTest`): drives the production Android classes `AnnexB`, `H264FrameLedger` (including `writtenEvent`) and `VideoWire` with the golden events and checks the exception type and message of each declared rejection it claims (config-only, multiple AU, missing parameter sets, B frame, duplicate PTS, non-integer PTS, time base, written PTS/capture time/calibration identity, dropped identity). `nativeProfileBuilderOutputSatisfiesStrictProfileSchema` checks that `CaptureProtocol.profile()` output (device and simulation) passes the strict Profile schema; the native builder itself does not enforce UUID recording IDs (SA-51). The remaining 55 rejecting cases (strict schema, CRC/layout, descriptor, channel encodings, clocks, tracking, calibration reset, counts, cardinality, outcome, sequences, malformed messages, profile, truncation, legacy) are proven by the Kotlin `ContractReader` only and are reported as `portable_only`, not as natively enforced. These android sources are not yet wired into the recorder (SA-51).
- **Swift**: runs on Linux Foundation only. It proves the contract and goldens are decodable in Swift, **not** that an iOS recorder, AVFoundation/VideoToolbox encoding or Apple-platform behaviour exists. The iOS capture implementation and physical qualification remain open.
