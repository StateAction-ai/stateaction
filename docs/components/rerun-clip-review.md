## One page and one viewer

Use `/clips/[clipId]` for both staff and customers. Open it from the Data browser dataset grid or staff All clips review queue (also reached by Pipeline → recording detail → Review clips); show a friendly title and parent breadcrumb, without a raw path/UUID chip or a Clip review sidebar item. The UUID identifies immutable RGB, observations and mapping from one accepted processing result. Labels and reviews remain outside the RRD, so a label change never requires rerunning inference.

Staff watch, edit the task label if needed, and **Approve or Reject**. The staff form also includes an optional Dataset multi-select. Approval saves the decision and selected memberships atomically after checking a nonblank label and current review/dataset revisions. Notes are optional. Only approved clips may be members; Reject/withdraw removes every working membership, and later reapproval does not restore it automatically. No inspection checkbox, acknowledgement, rejection dialog, other-clips section or large yellow callout. Customers get the same viewer with the currently authorized approved task label and no review mutations, internal notes or internal QC. Server capabilities control responses and mutations; hiding controls is insufficient.

## Worker artifact and bounded reads

Inside the existing `process_recording` invocation, write **one customer-safe `viewer.rrd` per clip**, plus a thumbnail. No new workflow stage or GPU is required. Start with a maximum 60-second clip, 128 MiB RRD and spatial review proxy at most 1280×720; these are proposed qualification limits, not measured capacity. Preserve native frame cadence and exact frame mapping. Shorten clip boundaries when necessary to meet byte limits; do not silently drop review frames. Keep native-resolution RGB/pose arrays separately for export.

Allowlist only clip RGB `VideoStream` samples, corresponding 2D points/edges, model-relative 3D estimates and safe missingness indicators. Generate the bounded spatial H.264 proxy from the single decoded-frame path, with no B frames and an independently decodable initial IDR/configuration per clip. Log one RGB entity with overlays as children, rather than duplicating the video for each view. Use separate left/right model-local 3D panes; their distance is not measured inter-hand geometry. Clear missing entities at every frame and omit edges with invalid endpoints, preventing stale hand drawings. Use explicit clip-relative capture/PTS mapping for video and overlays; do not rely on imported log-time defaults. Retain exact integer native clocks/transforms in the frame-map file. Quietly label the 3D pane **Model-relative 3D estimate**. [Video support/limitations](https://rerun.io/docs/concepts/logging-and-ingestion/video)

Reuse reviewed topology/conversion patterns from [the local visualizer](../../scripts/geometry_visualizer.py), not its complete audit RRD: existing diagnostics can duplicate images and contain staff-only metadata. No collector identity, internal note, raw source path, unrelated clip or hidden QC entity belongs in the shared RRD. A hidden Rerun panel is not an access boundary. Required outputs are hashed/API-completed/sealed with the other job artifacts. Retain RRDs/thumbnails while clips remain referenced; they are review assets, not a dependency of the portable training format.

The API authorizes the clip, then issues a short-lived direct R2 GET URL for the exact allocated RRD. Storage CORS permits the application origin. Qualify this pinned viewer's actual HTTP loading, cancellation and memory behavior; do not assume Range seeking or safe two-hour browser loads. H.264 web playback uses browser WebCodecs; test supported browsers/profile availability and clear capability errors. Local native viewing requires a qualified FFmpeg installation as described in the video docs. A **Reload viewer** action reauthorizes and replaces an expired/failed connection; keep form edits intact. No signed URL appears in the shareable page URL or logs.

## Automatic quality checks

Below the staff viewer, show a compact neutral **Automatic quality checks** panel populated from actual worker results. Each row has a name, status, measurement where relevant and short explanation:

| Check | What it establishes |
| --- | --- |
| Source checksum | Computed SHA-256 matches the sealed source declaration |
| MCAP / RGB decode | Source and required video frames decoded without declared errors |
| Frame mapping | Every output frame has its required source-frame/PTS mapping; not verified cross-clock synchronization |
| Landmark arrays | Expected 21-point shape, finite coordinates where valid, explicit masks for missing observations |
| Hand-detection coverage / missing frames | Frames with at least one detected hand versus all decoded RGB frames, plus separate side counts if available; percentages use this explicit denominator and are not anatomical accuracy |

Statuses are `pass`, `warn`, `fail`, `measured`, `not_evaluated`. A percentage alone is **measured**, not automatically a quality pass. Any threshold-based warning records its configured rule revision. Integrity/decode failures block result acceptance; the Pipeline shows their errors. A failed-preview mock illustrates recovery, not a reviewable accepted corrupt result. Anatomical accuracy, metric 3D and unqualified synchronization remain not evaluated. Customers receive none of this internal panel. Model/code provenance stays in durable manifests rather than substituting for check results.
