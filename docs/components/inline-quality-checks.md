# Inline quality checks and corrupt-candidate rejection (SA-32)

There is no separate QC engine. Inline quality evidence is produced by the existing `hand_pose_cpu_v1` worker path (`hand_pose_cpu_v1.py` → `artifact_export.export_artifacts` → `FrameStream`/`CaptureStream` → `HandInferencer` → `ClipWriter`) and persisted in the frozen `stateaction.processing_result.v1/v2` manifest `checks`.

## Statuses

`pass | warn | fail | measured | not_evaluated` (frozen schema). `measurements` are at most 16 int64-decimal strings. **They describe coverage and counts, never accuracy**: `metric_accuracy_validated` is always `false`, and `measured` is not a pass.

| Situation                                                                                                                     | Outcome                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Valid source, no hands detected                                                                                               | Success. `hand_detection_summary` is `measured` (counts only). Zero hands is a result, not a failure.                                                                                                                                                                                                                                                                              |
| Joint non-finite from the model                                                                                               | Masked in the arrays (`landmark_mask` false, NaN), counted as masked joints; never repaired. This is a truthful per-joint absence, not corruption.                                                                                                                                                                                                                                 |
| Malformed model result (shape, handedness, too many hands) or model error                                                     | `fail`: the job fails; no RGB-only success.                                                                                                                                                                                                                                                                                                                                        |
| Corrupt/truncated MCAP, bad CRC, decoder fault (including at the final flush), frame count mismatch, interrupted output write | `fail`: sink aborted, no manifest, no accepted clip.                                                                                                                                                                                                                                                                                                                               |
| Declared source SHA-256 differs from the whole-source hash                                                                    | Rejected **only at final EOF, after inference** (`E_SOURCE_SHA_MISMATCH`). Nothing is accepted or source-verified before then; the whole candidate is rejected.                                                                                                                                                                                                                    |
| Failure before a verified result                                                                                              | A diagnostic v2 manifest (`outputs: []`, `clips: []`, `source_eof_verified: false`, `verified_sources: []`) with one `fail` check plus `not_evaluated` `source_accepted` and `hand_detection_summary`. Already uploaded files stay in the closed, _failed_ inventory (retained, never accepted).                                                                                   |
| Failure after the source was proven (manifest build, contract validation or seal)                                             | Still a failed candidate with no clip or output. After proven EOF, SHA-256 and profile checks, `source_accepted` passes and `source_eof_verified` attests only the MCAP named by `source_file_id`; `verified_sources` lists that file with its measured size and digest, as in successful exports. Unread inputs are never listed. `hand_detection_summary` stays `not_evaluated`. |

## Annotation consistency (SA-92)

A recipe seal adds `annotation_files_consistent` to `checks`: every caption row names a segment of this job's `segments.json`, and the captions pin that exact segments file. `pass` or `fail` needs both documents read and validated (`measurements`: `segments`, `captions`, `unknown_segments`, `pins_segments_file`). When a file is absent (a failed or `not_run` stage) or the sealing stage cannot read it, the check is `not_evaluated`, never `pass`. Acceptance re-checks the same subset rule on the stored bytes (`caption_unknown_segment`). Today the job routes let only the caption stage read job outputs, so the check is `not_evaluated` in production until `hand_pose` may read `segments_json` and `captions_json`.

## Persisted counters

Success manifest: `source_accepted`, `decode_and_inference_once`, `capture_counts` (acquired, submitted, written, dropped, unresolved, video messages, sensor/pose events, unassociated and dropped-frame sensor events; all validated against the MCAP Close counts), `hand_detection_summary`, `native_mp4_remux`, `clip_bounds`, `proxy_rrd_bounds`. Capture clock, calibration and profile identity are carried exactly as the source states (unknown stays unknown; frame-map `timing_verified` is false).

Failure manifest: the exporter attaches curated `diagnostics` (`stage` ∈ `inference | source_verification | manifest`, integer counts only) to the exception; `_failure_evidence` copies only allowlisted names and non-negative integers (`source_bytes_read`, `video_messages`, `frames_decoded`, `frames_inferred`, `clips_written`, `files_put`) plus `files_uploaded` (the number of sink receipts) from the server sink. A count that is not an int in [0, int64 max] is omitted, never clamped. Exception text, paths and payloads are never copied. The exporter also attaches a boolean `source_verified`, set only at the proven final EOF/SHA/profile gate (false for a prefix failure or a SHA mismatch); `_failure_evidence` honours it only with stage `manifest` and a byte count, and never infers it from exception text. Counters are progress counters, distinct from the full-coverage `source_accepted` finalization of a success.

## Failure after a partial upload (server rules, migration 009)

`outputs/close` requires every output file to be `completed`/`verified` and exactly one result manifest (`SAC04` otherwise); for a `failed` outcome clip role sets may be incomplete. A failure after fully completed `put`s reports normally: the diagnostic manifest is sealed, the inventory closes `failed`, and the retained files are never accepted. An unfinished output upload makes close fail and `_fail` return `EXIT_UNREPORTED`. Existing missing-result settlement fails a running job after exact termination evidence and the finite result grace; incomplete outputs remain retained and no clips are accepted. The missed transition when evidence arrives after `needs_attention` is tracked in [SA-72](https://linear.app/hw-personal-projects/issue/SA-72/settle-overdue-jobs-after-late-execution-termination-evidence). No closure guard is relaxed and no partial bytes are marked complete or verified.
