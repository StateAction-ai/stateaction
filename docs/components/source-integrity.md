# Source integrity before upload (SA-18 core)

Mobile modules in `apps/mobile/lib/src/modules/source_integrity/` turn a closed capture into an immutable, owner-bound seal plan. They compute a local plan without network calls; the native completed-stop adapter supplies closure evidence. The network uploader and auth handoff remain SA22.

- `stable_hasher.dart` + `posix_fd_hash_backend.dart` / `android_channel_hash_backend.dart`: streaming SHA-256 over the **opened file descriptor**, confined under the session root. The backend opens the root, then `root/rel` with `O_NOFOLLOW`, `fstat`s the descriptor (regular file, dev, inode, size, ns mtime/ctime) and requires the descriptor's own kernel path (`/proc/self/fd/N`) to equal `root/rel` and `lstat(path)` to name the same inode, before the first read and again after the last. Bytes are read only from that descriptor in bounded chunks (default 1 MiB; memory is one chunk). A symlinked or swapped parent, a rogue directory swapped in and restored around open/read, growth, truncation, in-place rewrite, replacement and read failure never produce a hash and never touch the file. Hashing a descriptor whose directory is swapped away and back mid-read yields only the original descriptor's bytes. Limit: if a rogue file stays at the path through the final check it is indistinguishable from a legitimate replacement; the frozen journal fact then conflicts on the next hash.
- Backends: Linux host reference calls libc (`open`, `statx`, `read`, `readlink`) through `dart:ffi` on x86_64/arm64 and exercises the same guarantee in tests. Android uses `SourceHashMethodChannelHandler`/`ConfinedFdHasher`/`AndroidFdOps` (Kotlin, `android.system.Os`, worker executor, `cancel` supported; channel `ai.stateaction/source_hash`, registered by `SteraRecorderPlugin`). Android below 13 (API 33) reports only whole-second times and is refused as `unsupported`; other platforms get `FileIdentityUnsupported`. There is no path-based or size+mtime fallback.
- `closed_source_ack.dart`: the closure evidence the native recorder must supply (completed outcome, finite EOS drained, footer closed, zero unresolved frames, duration at most two hours, one MCAP, at least one recorder metadata file, any calibration sidecars). An early marker or path list cannot satisfy it. The actual SA56 completed-stop response is parsed by `ClosedSourceAck.fromNativeStop`; missing or incomplete closure is refused.
- `source_journal.dart`: append-only, hash-chained, fsynced journal per recording, outside the capture directory. First record freezes owner, backend origin, client recording id, create request and capture config digest; registration adds recording id and server `collectionPermissionRef`. States: `pending_registration` → `registered` → `closed` → `hashed` → `manifest_built` → `seal_ready`. A different current user or origin cannot read or advance it; logout/account switch keeps files and work under the original owner. Every transition is one serialized transaction on a per-file queue (validation, state check and append together), so concurrent callers cannot both pass a stale check. Differing replays of a frozen registration, closure, file hash or manifest record a durable sticky `conflict`; an exact identical retry is a no-op. Inputs are deep-copied and everything returned is deeply unmodifiable; the hash chain covers the persisted bytes of each line. `create` on an existing journal rejects a differing create request, capture config or session directory without altering the file.
- `source_sealer.dart`: freezes the versioned `http.recording-registration.v1` or `.v2` response after validating the frozen create request and exact v2 profile/provenance, freezes the full closure (inventory with required flags, clock domains, channels, counts; file ids derived from the client recording id) at close, hashes every inventoried file, writes the selected `artifacts.recording-source.v1` or `.v2` manifest atomically only after every replay comparison passes (it lists the other files and never itself; an existing manifest is never overwritten and a changed ack after seal leaves it intact and records a conflict), and builds the byte-exact `http.recording-seal.v1` body, checked with `checkSealedInventory`.

Caps: 100 GiB per file, two hours, 2000 seal files, 1 MiB manifest (`source_limits.dart`).

Not covered: SA54 calibration sidecar paths, SA55 depth files, SA68 schemas, SA22 owner-ledger/network uploader handoff, and physical-device qualification. Native closure and the actual Dart-through-MethodChannel path are covered by the emulator evidence below.

## Android channel bounds and race semantics

- `hash` arguments are type-checked before any allocation (`SourceHashArgs`): `token` 1..128 chars, `root`/`relativePath` 1..4096 chars, integer `chunkBytes` 1..16 MiB (default 1 MiB, one heap buffer per call), integer `maxBytes` 1..100 GiB (`common.v1 fileSizeBytes`). Anything else, a non-map argument, or a live duplicate token replies `bad_args` (Dart: `FileIdentityUnsupported`); the Dart backend also refuses out-of-range values before calling native.
- Cancellation: a request already cancelled when `hash` is called never reaches native (`HashCancelled`). Otherwise the `cancel` listener is attached only after `hash` has been sent; channel messages are ordered, so native has registered the token before any `cancel`. `cancel` for an unknown/finished token is a no-op. Originals are never modified on cancel or error (read-only descriptor).
- Tokens carry a per-isolate nonce plus counter. The native map uses `putIfAbsent` and removes only its own entry, so a duplicate cannot overwrite a running call's cancel flag.
- A disposed or shut-down executor (`RejectedExecutionException`) replies `unsupported` immediately; `dispose()` flags every live call cancelled, and queued work still replies.
- Real channel proof: `scripts/source_hash_probe.sh` runs `apps/mobile/tool/source_hash_probe` (headless service, FlutterEngine, real `SteraRecorderPlugin`, Kotlin `Os`) on an emulator only.

Native SA56 stop binding now emits a private `stateaction.native_source_close.v1` packet only after encoder EOS, completed Close, container fsync and final metadata readback. It inventories the actual registered channels, MCAP mapped Unix clocks and native payload clock domains, exact writer counts and final MCAP/metadata names. The Dart adapter rejects incomplete responses and retains the native recording ID and finalization token for SA22 to bind to its owner ledger and session root. This packet does not change the published MCAP wire schema or admit an upload.

On Android API 33+, the recorder opens the finalized source files and checks their descriptor and path identities. It reads the final metadata token from that same descriptor with a 1 MiB limit. The atomic `FINALIZED` entry in `finalization_journal.json` stores the private `source_identity` object. Stop echoes it as `sourceIdentity`. It binds the finalization token to the session directory device and inode and the exact required inventory's device, inode, size and nanosecond mtime/ctime. Final metadata contains no identity or digest for itself. The sealer checks the frozen identities on the opened descriptors before reading source bytes and repeats its descriptor stability checks after hashing. A replacement conflicts even if it has the same path, size and bytes.

The MCAP writer records its exact filename and snapshots its still-open descriptor after writing and syncing the footer. Stop requires the session's sole MCAP to have that name. The descriptor reopened for final source evidence must match the writer's identity. This check starts at the post-fsync snapshot. Independent container validation checks the MCAP contents captured at that point. If the writer could not capture the identity, a valid local recording remains recoverable without upload evidence.

Existing native receipts without this field retain their original files. An unsealed receipt without close identity stays blocked. An existing `seal_ready` journal can replay only when every descriptor identity and digest still matches its frozen hash record. Captures with unstable or unavailable identity remain available for local recovery, including captures on Android below API 33. iOS remains deferred.

SA22's cold-start reader must pass the validated FINALIZED journal's `source_identity` as `sourceIdentity` when reconstructing a Stop acknowledgment. Run the guarded API 33 emulator test `completedStopPublishesFinalSourceClosure` to compare the durable journal with Stop and hash the originals using the recorded identities. Run `sameNameMcapReplacementAfterWriterCloseDoesNotPublishSourceIdentity` to check that a byte-identical replacement in the interval before Stop publishes its evidence cannot qualify. SA22's joined Flutter seal test must also use the originals in that session directory. Copied fixtures can still verify byte hashes. Copying changes the filesystem identities and cannot qualify a seal.

The actual ROS schema name `geometry_msgs/msg/PoseStamped` cannot be represented by the frozen recording-source.v1 schema-name pattern. This branch adopts SA71 recording-source.v2 additively and bundles catalog-v6 roots plus their exact transitive schema documents into the app. A journal whose frozen create request is `stateaction.recording_create.v2` selects v2 registration and source validation; simulation provenance is preserved, including unknown values, with only documented HTTP/artifact field spelling translated. Native recording ID and finalization token remain frozen in the closure journal, independently of client and server IDs. Existing v1 journals are never upgraded; an actual native closure against one stays blocked as `native_requires_source_v2`, retaining its bytes. SA22 still must select v2 at session creation and connect the owner ledger/network handoff.
